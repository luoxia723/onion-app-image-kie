# 白底蓝框适配

用户已确认的制作分支：`geometry_report()`算出的常规cover预计裁切达到6%（含6%）时，使用白底蓝框生成、OpenCV去框、直接拉伸到目标尺寸；低于门槛沿用常规适配。阈值由`scripts/kie_model.py`维护。双图和三图按每张图的目标尺寸分别判断；原有禁用版位保持禁用。

## 生成前

配置保存后，先运行：

```sh
python scripts/blue_frame.py --config <02_过程/image-config-result.json> --output-dir <02_过程> --label 参考图2
```

命中分支时会生成`blue-frame-guide.png`和`frame-layout.json`，返回参考图对象和必须使用的`prompt_rule`；未命中时返回`enabled=false`，不添加蓝框。参考图是纯白底加单个蓝框，框内按目标比例绘制；具体画布坐标由脚本计算，不手填。

将返回的参考图放在Logo、IP之后，其他风格参考和字体之前；`--label`使用实际顺延编号。例如无IP时常为“原版Logo1、蓝框2、字体3”，有IP时相应顺延。保留至少一张用户选择的原版品牌或字体等资产，蓝框不能单独代替真实参考。蓝框是代码生成的制作参考，允许使用本轮`02_过程`中的文件，不写入全局品牌资产清单。

每个命中job填写`frame_layout_path`，并逐字使用返回的蓝框范围规则；其余文案、场景、视觉体系和原版资产仍由当前配置决定。整张广告及其背景都生成在框内，框外纯白，蓝框保持原位置供代码识别。旧的“全画布延伸背景”和百分比边缘留白段在本分支被替换，不能叠加。Logo位置仍遵守渠道规则，指框内的左上角或上方居中。

```json
{
  "frame_layout_path": "<02_过程/frame-layout.json>",
  "size": "720x1559",
  "references": [
    {"label": "参考图1", "role": "原版Logo", "path": "assets/logos/onion-logo-standard-001.png"},
    {"label": "参考图2", "role": "白底蓝框构图模板", "path": "<02_过程/blue-frame-guide.png>"},
    {"label": "参考图3", "role": "字体参考", "path": "assets/font-references/字体参考-30.png"}
  ]
}
```

这是字段片段，不是可直接执行的完整job。执行`direct_batch.py --validate-only`检查配置、参考图哈希、尺寸、编号、范围规则和依赖；达到门槛但缺少蓝框配置时在付费前停止。付费授权和模型1K规则照旧。

## 生成后

`render.py`保留下载原图，调用`scripts/blue_frame.py`中的处理函数：

1. 模板坐标只限定外围搜索带。OpenCV用HSV颜色阈值和横竖长线识别每张实际框线，检查位置、线宽和矩形比例，不全图删除蓝色。
2. 裁到实际框线内沿，再内缩2个原图像素以去掉过渡色；宽高分别缩放到目标像素，允许轻微拉伸，不再做第二次按比例裁切。
3. 无损结果写入`03_候选/框内预览`，记录原图及结果哈希、实际坐标、内缩量、宽高缩放倍数和形变比例。`image-render-result.json`的`filepath`保留原图，`candidate_filepath`指向去框结果，选择页展示后者。
4. 额外裁切以模板框内范围为基准单独记录；外围白边和辅助框的舍弃面积不能冒充广告内容被裁比例。新增框内裁切达到6%或放大至少1.25倍时追加复核提示。

找不到可靠四边、存在多个近似框或框形异常时，记录`frame_status=needs_review`并展示原图，等待人工检查；不擅自扩大裁切、不自动付费重做、不打断其余已授权生成。蓝框是柔性参考，不是API硬蒙版；该流程不修复Logo失真、错字或已经生成缺失的内容。

用户采纳后，交付脚本从该job的原图复用同一配置去框拉伸，再按KB上限压JPEG，不按原图重新cover裁切。检测未通过的图片不能写成正式交付；保留原图、预览和诊断供后续处理。历史任务不自动补图、不回写Prompt、不重新扣费。

# 工作台统一逻辑

以当前用户确认的流程为准：一份确定形式的文案可分发至多个兼容版位；每个版位独立制作、挑选；交付只包含完整且规格合格的套图。术语见根目录 CONTEXT.md。

## 输入、草稿和资料

- 文案形式与文案放在同一卡片。单图主/副标题，双图两句，三图三句；版位只展示兼容组合，同形式允许多选。
- 三种文案草稿独立，切换不会串句。草稿保存到本机 SQLite，刷新、重新启动后可恢复。浏览器不存任务正文或 Key。
- 每份草稿有自己的标识、版本及编辑序号，拒绝其他窗口的过期覆盖；提交/删除后的迟到保存不能复活草稿。
- 产品资料在设置中维护，任务冻结其全文及版本。资料为空时规划只能依据确认文案，不能补造产品功能、数字、承诺或真实界面。
- 展示文案与文件名分离。自动文件名替换不安全字符；用户显式填写的方向名仍严格校验。

## 修改的影响范围

| 操作 | 行为 |
| --- | --- |
| 增加兼容版位 | 在当前轮次新增该版位的套图，保留已有图片和预选 |
| 增加统一套数 | 只补足各版位尚不存在的方案 |
| 某版位再出一套 | 只为这个版位新增方案并规划画面 |
| 修改文案、产品资料或美术要求 | 冻结为新轮次；停止旧轮未提交部分，已提交图片收完结果；保留旧轮成果 |
| 重试失败图片 | 使用已存提示词，不重新随机；图1重出时带动本套后续图 |
| 补齐这套 | 只处理本套失败/停止图片；首图失败从首图开始 |
| 重命名、修改通用设置 | 不触发生成 |

参数中的版位/方案数是补充目标；减少目标不会删除已经生成的历史结果。交付范围由勾选控制。文案内容相同但没有新增目标时，不产生新的生成任务。

## 原 Skill 画面规划

运行代码没有固定场景池。`local_app/scene_planner.py` 直接调用语言模型 API 的 `/chat/completions`。按用户选择，默认网关为 `https://ops-ai-gateway.yc345.tv/v1`，模型为 `gpt-6.1-terra`；不再依赖 Codex CLI。设置面板维护规划 Key、地址和模型，Key 只存本机 `.env`，不进入浏览器存储、任务快照、日志或交付包。

每轮保存原 Skill 规则快照。规则来源为根 SKILL、随仓库的 visual-scene-planner、艺术定调和 APP 规划适配的方法部分；数学示例不作为场景池传入。文案、产品事实、已分配画风、IP 和目标版位作为引用资料传入，不能覆盖规划指令。

先调用原 `assign_styles` 冻结画风与素材，再按画风→世界场景→人物处境→逐张动作/镜头→光色规划。模型不能改文案、素材身份、画风分配和版位身份。原 `plan_directions` 和 `positive_prompt.compose` 继续负责原格式校验及最终 Prompt 编排。

规划每次最多处理3套，完成一部分就可以进入出图队列；其他批次有机会取得规划名额。完整响应未通过结构或合同校验时最多做2次结构修正；网络、鉴权、限流、超时和未完整结束的响应不自动重试。再次失败则明确报规划失败，保留结果以供重试；不退回模板。规划结果、规则指纹、输入指纹和实际 Prompt 均保留。

API 调用用 system 消息传入原 Skill 方法和 JSON Schema，用 user 消息传入冻结资料；不赋予模型工具执行能力。请求使用 `response_format: {"type":"json_object"}`，本机继续严格校验 Schema 和原 Skill 合同。网关返回的原始错误不回显，不自动跟随重定向。停止后丢弃迟到结果，不继续提交图片；已经抵达远端的规划请求可能仍计费。

规划缓存指纹包含网关地址、指定模型、规则、Schema 和输入；修改网关或模型不会误用旧缓存。成功结果记录实际调用的配置、规则与输入指纹及返回的 token 用量，不保存密钥。兼容请求格式依据 [OpenAI Chat Completions 文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)；本网关的可用性由真实调用验证。

**模拟模式只模拟图片输出，画面规划仍真实调用此 API，消耗网关额度。** 未配置规划 Key 或连接失败时停在规划阶段。单元测试的规划替身仅在 tests_local 中注入，运行程序不会导入它。

## 生成、挑选、交付

设置中保存新的 KIE Key 默认启用真实生图；显式选择“模拟预览”时以用户选择为准。不需要手动改 `.env` 或重启；新提交使用当前模式，已有轮次的模式保持冻结。没有 KIE Key 不能启用真实生图。连接测试只调用余额查询，不上传参考图、不生成图片；保存设置也不发起图片任务。型号沿用原仓库 `gpt-image-2-5-sunburst-image-to-image`（GPT Image 2.5 Sunburst）、1K，符合 [KIE 官方接口](https://docs.kie.ai/market/gpt/gpt-image-2-5-sunburst-image-to-image)。


- 不同版位、不同套可并发；图2/3只在本版位本套图1成功落盘并通过哈希检查后提交，仅引用图1原始 PNG。
- 停止后续只停止未提交图片；状态不明只恢复查询，不盲目重提。已提交的任务继续收结果。
- 生成状态、预选状态和交付状态分别返回。已保存版本不会因更改选择而从历史中消失；显示“已保存 vNNN · 选择已变更”。
- 按版位分组并排比较方案。点击卡片空白处或复选框预选，点击图片预览。全选/取消只作用于当前渠道与筛选的可见可选套图，支持部分选中状态。
- 预选可以提前发生，正式交付必须整套完成且规格通过。已选套图有未完成或规格问题时，保存按钮不可用并能定位问题；不要求未选版位全部完成。
- 挑选页可直接保存图包到本机保存位置，无需先跳下载页。交付记录支持下载副本和查看实际采用图片。
- 图包指纹包含版位、方案、图号和文件 SHA-256，不以重试次数决定包号；相同内容复用旧包，新内容建立新包，旧包不覆盖。
- 历史记录不自动过期。归档与删除分开，清理暂存文件保护任务、图片版本和草稿引用，历史图片与交付包保留。工作区有 OS 文件锁，重复启动不会重复恢复/提交任务。

## 既有任务

历史提示词、图片和交付包不改写。历史固定场景模拟任务明确标注；若要重新制作，需要复制成新任务进入原 Skill 规划，不允许继续以旧模板生成。


## 去框与成品预览

原图落盘后先通过 OpenCV 检测蓝框四边、去除框线与框外白边，再将框内画面适配到目标尺寸并压缩为 JPEG。模板位置附近未找到边框时，可检测实际完整外矩形；必须有四条可靠长线和纯白外侧，不推测缺失边框，不在多个/嵌套矩形间猜选。比例调整达到4%会提示确认人物和文字效果。

默认预览是处理后的成品，提供“查看原图”切换。识别失败时显示完整原图和“自动去框失败，暂不可交付”，不再把原图按 cover 居中裁成假成品。失败图可以“重新去框（本机处理）”；套图“补齐”遇到纯裁切失败也先做本机处理，不因此发起生图。

本机重新去框保留原 PNG、旧 JPEG 和既有交付包，追加图片版本并取消该套的勾选，待用户查看新结果后重新勾选。无可靠框线时继续保留待处理状态，不自动付费重做。


## 部分交付与整图适配

全选表示预选，不代表所有图片已达到交付条件。全部保存仍严格检查整套完整性、版本、像素尺寸、大小和哈希。存在不合格套图时，界面提供明确的“保存可交付的 N 套”；只有显式传入 `ready_only=true` 才排除不合格整套，不能从不完整的多图套中挑出个别图片交付。其余勾选保留，清单记录 `excluded_suites`，已交付子集可复用图包，仍有待处理选择时不会触发已交付清理。

对模型未绘制蓝框的原图，可明确选择 `fit-image`：OpenCV 整图缩放至目标尺寸，无内容裁切，不伪称识别了蓝框，标记 `full_image_fit` 并提示确认比例。追加本机处理版本，保留原图、旧文件与该套预选，更新其采纳版本；不调用任何模型 API。

缩略图只展示简短状态标签，完整原因置于卡片说明和大图预览，不覆盖整张窄图。侧栏区分“待处理”和“待挑选”，底部说明本次导出的范围。


## 客观规格保障，视觉由人挑选

不设置视觉复核表，也不因比例或画面效果提示阻止导出。用户通过预览和勾选挑选视觉效果；之前的视觉复核元数据不参与交付判断，历史包也不因缺少视觉确认被拦住。

硬性检查保留：每个版位精确宽高、实际 JPEG 编码和 RGB 模式、渠道体积限制（区分严格小于与不大于）、可完整解码、SHA-256、采纳版本与当前版本一致、套图张数及图序齐全。去框失败或未完成规格适配的结果不可交付；明确选择的整图适配只要硬规格通过即可交付，不再额外要求人工勾选。

生成和保存阶段检查实际文件。新图包生成后检查 ZIP 清单、图片数量/路径、字节、尺寸、格式、哈希及选择指纹；复用和下载时再次检查 ZIP。损坏的旧包保留，新保存创建新版本，不复用损坏文件。只保存可交付套图必须显式选择，不从不完整多图套里拆出部分图片交付。


## 等待与离开页面

任务由本机服务运行，切换任务或关闭网页不会取消制作；用户稍后可从侧栏任务返回。必须保持本机服务运行，关闭启动窗口、关机或休眠会影响处理，不宣称离线云端后台保障。

头部持续显示阶段与实际图片完成数量；等待区给出规划方案就绪数量、处理中图片和等待首图数量，并展示等待动画及离开页面说明。规划耗时没有可靠估计，不使用虚构百分比或倒计时。双/三图的后续图明确标为等待首图。停止后已提交图片仍在执行时继续显示其状态。

连续两次无法刷新时提示无法连接本机服务，说明当前只是上次进度；连接恢复后自动更新，不将断线解释成任务失败，也不继续承诺后台必然运行。


新的上下文分配设计见[单图与套图上下文合同](prompt-context-contract.md)，目前为设计整理，尚未替换运行代码。原则是保留单图基线，整套资料用于规划，实际生图按首图／分支分别提取当前画面所需内容。

## 按张重出与恢复查询

- 预览中重出图2／图3，只建立该张新版本，继续引用本套本版位当前首图的原始PNG；其他图保持当前版本。
- 重出图1，会将整套建立为新版本，后续图退出当前结果，等待新首图完成后以新首图生成。旧文件与已保存交付包保留。
- 分支被首图阻塞时，按钮定位首图，不把分支重出请求隐式转成整套重出。
- 本机查询等待超过240秒不代表供应商失败。保留任务号，仅恢复查询；工作台不因超时自动另交一次。补齐套图也优先恢复未确定的任务。
- 整套仍有生成中或状态未确定的任务时，先等待或恢复查询，再重出首图，避免覆盖未完成任务。

## 分块提示词与人工自由编辑（2026-11-02）

新自动任务使用任务、画面描述、画面文字、参考图用途、保持与变化、画面约束等可读分块。准确文案使用引号，并交代层级和次数。参考编号与实际上传数组一致；分支仅列首图参考。

人工在预览中提交的提示词标记为 manual，原样保存和发送，允许换行、改变文案或删除系统固定句。只要求非空且不超过30000字；后端入口和工作进程均跳过系统文案、Logo句式及蓝框句式检查。真实素材绑定、参考文件完整性、蓝框配置与首图回执、请求指纹和任务依赖继续检查，交付仍检查文件规格。后续不带新文字的重试继续使用人工提示词。

已完成轮次可依据其冻结的方案和素材，通过 rebrief-round 建立新轮次重出。保留原轮次及交付包；相同来源的重复请求返回已经建立的新轮次，不再提交另一批。旧方案的整套 prompt 不直接进入套图首图，而从已保存的世界、场景、光色材质提取共同视觉，逐张沿用各自动作。此操作不额外调用规划API。

## 图片模型切换

任务表单可选择 GPT Image 2.5 Sunburst 或 GPT Image 2，均固定1K；设置可保存新任务默认模型（ONION_IMAGE_MODEL）。选择保存到制作轮次和工作进程快照；修改模型后提交建立新轮次。旧轮次重出、补图和恢复查询沿用该轮原模型，历史缺省模型为原Sunburst，不根据当前默认值回填。

每个模型按KIE支持的比例选择画幅，必要时使用对应比例的蓝框；GPT Image 2 请求使用 gpt-image-2-image-to-image，固定resolution=1K。参数依据：[KIE官方图生图接口](https://docs.kie.ai/market/gpt/gpt-image-2-image-to-image)。模型选择计入请求指纹，恢复查询不改变模型、不重复提交。

## 停用字体样张

用户指定停用的“作业卡壳，别干等”样张为 assets/font-references/字体参考-06.png，由 config/font-library.json 统一登记。新任务随机字体池和素材选项排除该样张；其他样张仍可使用。原文件不删除，历史轮次已冻结的参考路径、预览、重试和下载继续有效，不改写历史提示词或触发重新生成。

## 整体优化实施

2026-11-02：调度、交付、历史/草稿视图及KIE执行已分别收敛到 scheduler、delivery、workbench、kie_client 模块。全局并发即时生效，规划和图片任务轮转；暂停不改变图片版本；下载、图片处理、打包及文件传输不占用全局状态锁。KIE适配不再临时替换全局函数，上传缓存采用可随进程退出释放的文件锁。

任务列表提供摘要接口，当前轮次与预览详情按需获取。修订号避免重复传输，未变化不重建页面。提示词草稿按图片版本和编辑窗口保存，历史参考与历史图片按实际版本读取。数据库升级自动备份，保留原任务ID、目录、提示词、回执和图包。

# 通用画面规划在APP图片中的适配

设计新画面或诊断故事、动作与机位冲突时，先读随本包提供的[画面叙事与关系规划Skill](../skills/visual-scene-planner/SKILL.md)，再按本文件映射到现有字段。独立Skill负责可复用的设计方法，本文件负责洋葱APP约束；无需另行安装依赖即可随本包使用。

## 固定输入和艺术决策

先冻结确认文案、产品事实与配置。创作决策仍按画风→世界与场景→叙事瞬间→动作与镜头构图→光色材质展开。主画风按现有77条风格库按套分配，字体/IP按已保存选择确定；场景、时代、故事和机位依据画风与文案联合设计，不增加随机维度。

每张都有学习者：有IP时用选定IP，无IP时用原创学生。此项是APP业务合同，通用Skill中的主体自由度不覆盖它。IP保留识别特征与原服装核心配色、轮廓，少量时代或风格配饰在同套连续；人物参与当前短句的学习处境，场景与装饰强化这个瞬间。

以下原合同继续由各自模块负责：[固定项](visual-invariants.md)、[七类视觉约束与参考用途](prompt-rules.md)、[KIE合同](provider-contract.md)、[渠道与比例处理](model-size-compatibility.md)。Logo原版组合和位置、独立字体体系、已配置CTA按钮、确认文案与功能事实继续进入实际Prompt；2.5/1K、引用依赖、蓝框阈值、费用、恢复和交付由原代码流程执行。

## 直接复用现有计划结构

| 规划结果 | 现有承载字段 |
|---|---|
| 谁遇到什么困难，产品帮助和可见推进 | `learner_story.protagonist/pain_point/product_action/visible_change` |
| 画风选择 | `style_id`及分配结果；用户指定项继续优先 |
| 世界、地点、整套故事与光色 | `art_direction.world/scene/story/lighting_materials` |
| 基础空间、镜头可见面、阅读路线和信息留白 | `art_direction.composition`；需要模型执行的内容也写入`prompt` |
| 同套共用的具体场景、人物与道具位置 | `visual_concepts.prompt`；不在共用段写仅适用于后续张的动作 |
| 当前瞬间、姿态、视线、接触支撑与本张必要的机位变化 | 对应的`slot_actions`，图1/2/3分别写清；分支不能只写“保持合理关系” |
| 清晰示意或真实UI及其内容依据 | 原有`screen_ui_mode`、`screen_text`和job的`ui_text` |
| 全文与原版参考图用途、逐字文案、CTA和约束 | `positive_prompt.compose`与原有manifest，不增设Prompt格式 |

内部关系分析只保留对当前画面有用的决定，不增加统一必填场景图、庞大JSON或新的历史配置版本。已有五层定调不自动进入Prompt；必须把实际需要模型执行的镜头、位置和接触关系写入共用场景及对应动作。

## 用原数学案例设计单图、双图、三图

确认事实：洋葱AI按目标和基础安排每日任务，支持查看当天任务和学习进度。单图主副标题、双图两句、三图三句均按各自确认稿使用。表中是同一内容的设计示例，不替代实际随机抽到的画风，也不锁定以后场景。

| 形式与当前文案 | 当前瞬间与可见证据 | 动作和镜头规划 |
|---|---|---|
| 单图：“这周我想把数学补起来”＋“洋葱AI按目标和基础排每日任务” | 学生想补数学却在不同章节间犹豫，刚看到今日任务起点，仍是准备开始的状态 | 窗边书桌上练习册平摊，学生握笔停在纸面上方，视线看向支架上的手机；屏幕朝学生，镜头从侧后方观察，侧脸、笔和“今日任务”同时可见 |
| 双图1：“这周我想把数学补起来” | 学生在古代幻想书院的长桌前翻到不同数学章节，眉头微皱，拿不准起点 | 一手压住当前书页，另一手持笔暂时抬起；斜侧机位呈现目光落点、题页和表情，给竖版标题保留上方空间 |
| 双图2：“洋葱AI按目标和基础排每日任务” | 同一学生看清每日任务，指尖正落在第一项，肩部稍放松 | 手机由桌面支架承托，学生已把笔放在册旁，单手点屏；侧后方机位呈现屏幕与侧脸，改变动作同时延续书院和角色设定 |
| 三图1：“这周我想把数学补起来” | 中世纪启发的幻想藏书室中，学生在几页不同章节的数学练习间犹豫 | 学生靠长桌坐稳，一手翻起题页、一手压住册页，斜侧机位强调犹豫目光；纸页、木桌、石窗按本套抽到的画风呈现 |
| 三图2：“洋葱AI按目标和基础排每日任务” | 同一学生看到按目标和基础排好的今日任务，开始第一道练习 | 手机立于桌面支架，屏幕朝学生；右手握笔、笔尖接触平摊练习册，左前臂靠在桌面，镜头从左侧后方越肩看清任务与书写关系 |
| 三图3：“打开看今天学啥学完看进度” | 同一学生完成当前练习后查看进度，练习册旁放着已放下的笔，神情踏实 | 学生一手轻点支架手机上的“学习进度”，另一手扶在桌沿；保留屏幕、手和侧脸可见的机位，数学练习册与完成状态支撑当前信息 |

每张只定格当前状态。共用场景段不预写所有阶段；首张负责困难时，不用“轻松庆祝”抵消痛点。原确认功能作为绘图依据传入，但不能因此要求首张同时演完从犹豫到完成的全过程。纸页路径等视觉隐喻可以强化任务推进，不能替代人物或新增承诺。

概念UI和纸面信息都依据确认事实，数学案例的辅助内容也围绕数学。优先用相关题页、任务状态、表情和动作说明故事；不靠铺满说明文字或新增成绩数值表达“有帮助”。

## 编排与检查

完成`prompt`与逐张`slot_actions`后，按原命令生成`visual-plan.json`，由`positive_prompt.compose`合成一段正向自然语言；实际参考图、文案层级、Logo/字体、CTA和分支整体替换规则继续按原合同加入。无需把内部检查表或对照分析灌进模型输入。

首张仅用本轮原版资产，后续张仅用同套图1原始PNG。分支的参考图1是完整广告图，保持本套美术与资产体系，并明确本张动作、必要的机位调整和当前文案整体替换；不能把Logo或字体参考当作整幅画风来源。

付费前除原静态预检，再由Agent核对每张的可见证据与动作、机位是否相容。生成后按实际图检查：人物与痛点、屏幕正反面、手与物体接触支撑、文字、Logo/IP/字体、CTA、画风及小图可读性。记录具体偏差，不把字段完整或通过预检当成视觉通过。内容偏差沿用现有候选提示和用户采纳流程，不自动增加付费重试。

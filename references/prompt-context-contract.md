# 单图与套图：上下文分配合同

日期：2026-11-02。状态：已用于新建双图、三图的规划与提示词组装；历史Prompt保留；经用户确认，新任务使用分块版式，单图沿用原有画面规划内容。静态测试不能证明视觉效果，尚需实际生图对照。依据：[本批实际提示词调研](research/2026-11-02-multi-image-prompts.md)、[原画面规划适配](scene-planning-app.md)、[原Prompt合同](prompt-rules.md)。

现行图层更新：新普通任务不向模型上传Logo素材，首图为无Logo底图，后续张仍引用该无Logo首图PNG；品牌标识在本机按冻结模板叠加。下文原版素材指IP、字体与实际选定参考，不包含Logo。安全区见[自然画布](natural-canvas.md)。

## 核心决定

**单图、双图首图、三图首图都是“从原版素材创建一张完整广告”。后续图是“引用本套本版位首图，生成当前另一张广告”。**

整套规划能理解全部内容，实际绘图请求各自只承担当前画面。不能把整套规划文本直接作为首图的总Prompt。已有单图效果作为内容回归基线，优先修双／三图的上下文分配。经用户确认，提示词编排可分块，不再要求一段式。

这不是保证改写一定提高出图质量；它先消除已观察到的职责混杂，效果仍需固定素材和参数进行对照。

## 一、上下文分成五类

| 类别 | 保存什么 | 谁需要它 |
|---|---|---|
| 已确认输入 | 本轮文案、产品事实、CTA、人物选择、画风／字体分配、版位与补充要求 | 规划理解全文；绘图只取当前适用部分 |
| 整套叙事 | 各句承担什么传播任务、每张的状态与变化、各方案如何不同 | 规划；留在计划记录中 |
| 共同视觉设定 | 画风的具体表现、角色身份、共同世界与空间、配色光色、品牌与字体体系 | 规划；首图使用完整必要设定，分支围绕首图使用必要的保持约束 |
| 当前画面任务 | 当前文案、这一张的可见证据、动作表情、接触支撑、机位与阅读布局 | 当前这一张的绘图请求 |
| 执行与交付记录 | 图片归属、依赖、原始PNG、回执与哈希、比例参数、像素／KB、并发、重试和版本 | 本机代码；不灌入画面描述 |

“产品事实全文”“整套叙事”和“共同视觉设定”是不同内容。例如图1负责呈现问题时，不应把整套解决过程或后续完成状态提前画进图1；确认功能可以作为规划依据，但只有当前需要被看见的部分进入绘图描述。

## 二、每种情况下到底给什么

| 场景 | 规划时允许看到 | 这次生图需要的文字上下文 | 这次实际图像参考 | 不进入这次画面的内容 |
|---|---|---|---|---|
| 单图 | 主／副标题、相关事实、已保存配置 | 当前主／副标题、已配置CTA、一张完整广告的场景／动作／镜头／层级、资产职责 | 本轮IP、字体，以及实际启用的画风／构图／UI／用户参考 | Logo素材、无关历史文案、其他方案说明、内部执行信息 |
| 双图图1 | 两句确认稿及各自叙事职责 | **短句1**，完整的首图画面任务、共同视觉设定与原版资产职责；CTA仅在已保存时使用 | 本轮原版资产，按实际请求独立编号 | 短句2的显示要求、图2动作、“第二张引用第一张”的执行说明 |
| 双图图2 | 原整套计划与当前第二张任务 | **短句2**、从图1保留什么、当前改变什么、当前动作与机位 | **同轮次、同版位、同方案的图1原始PNG，且只有这一张** | 原版素材重复上传、图1正文继续显示、别套／别版位图片、笼统“全部不变” |
| 三图图1 | 三句确认稿及各自叙事职责 | **短句1**，独立、完整的首图画面任务，与双图首图同级 | 本轮原版资产 | 图2／3动作、短句2／3的显示要求、整个流程说明 |
| 三图图2 | 原整套计划与当前第二张任务 | **短句2**、稳定视觉锚点、本张独有的状态变化与文字替换 | 本套本版位图1原始PNG | 图3内容；不因为有第三张就把图2画成过渡占位图 |
| 三图图3 | 原整套计划与当前第三张任务 | **短句3**、稳定视觉锚点、本张独有的状态变化与文字替换 | **仍是图1原始PNG** | 不默认改为引用图2，不叠加图2全部偏差，不捏造未确认结果 |
| 补充一个版位 | 原确认稿、共同创意、此版位约束 | 仅此版位当前一张的构图；必要时独立调整镜头与留白 | 此版位首图从原版资产创建，后续只用此版位首图 | 不拿其他版位首图当新基图强行拉伸，也不把全部渠道混入一个请求 |
| 新增一套方案 | 原确认稿、已保存配置、已有方案的必要摘要 | 新方案自己的世界与画面任务，确认稿保持不变 | 按新方案冻结的原版资产 | 已有方案的Prompt、旧广告内容作为当前执行指令；差异不只是换IP或标题 |

品牌Logo自带标准字由本机原版素材呈现，不等于图片模型需要绘制的广告正文。分支可以提到原标题，**但只能作为“需要被整体替换的对象”**，不能同时将新旧标题都当成要显示的文案。

## 三、双图首图怎样回到单图的质量基线

首图不承担“介绍这一套将怎么生成”的职责。它应像单图一样，单独看也是完整广告：

1. 一个明确的当前传播任务。
2. 一段真正支配人物、道具与环境的画风表现。
3. 一个人物正在发生的瞬间，以及能成立的手、物、视线和机位关系。
4. 当前确认标题的明确位置、层级、字形体系与完整排布。
5. 品牌区与每张素材的准确职责。
6. 当前已配置的CTA和相关事实；空字段保持空，不为凑版式补副标题或按钮。

区别主要是文案来源：单图取主／副标题，套图首图取短句1。不能因为只有四字短句，就把原本完整的广告降成“人物场景＋随便放一句标题”；也不能擅自给四字稿扩写一段新卖点。

当前“拍题精学”的首图应先说清：这是拍摄题页的一个瞬间，人物与题纸如何成立，四字标题如何成为阅读焦点。它不需要知道“第二张写一拍就会，并引用第一张”。后面这句话属于执行规则，而非当前画面内容。

## 四、参考图按职责解释

参考图编号以每次实际数组为准，不把“参考图1永远是Logo”当成全局规则。分支的参考图1就是完整首图。

| 参考类别 | 提供什么 | 如何与其他上下文配合 |
|---|---|---|
| Logo | 模型只接自然背景留位，原版素材留在代码 | 生成后在精确尺寸上叠加，不进入绘图参考数组 |
| IP | 角色身份、识别特征、服装轮廓与核心配色 | **身份沿用原版，画法与材料服从本张画风。** 折纸／刻纹的具体人物适配要写出，不把“原版外观”解释成永远保留原动漫渲染 |
| 字体样张 | 目标标题的字形骨架、笔画、描边与排版体系 | 把样张字形映射到当前确认标题，整句完整替换；样张不兼任第二个品牌区或额外旧广告贴纸 |
| 真实UI | 用户提供、已确认的实际界面 | 仅在确实需要展示该界面时使用；未给出的产品功能、界面原文与数字不推造 |
| 风格／构图参考 | 用户注明的局部视觉意图 | 只使用确认用途；不把参考中的旧文案、品牌或产品事实一并带入 |
| 自然画布安全区 | 当前版位中完整保留人物与文字的范围 | 画面要求进入提示词；固定窗口、精确像素和压缩由代码处理 |
| 已生成首图 | 本套实际形成的视觉锚点 | 分支说明角色、世界、画风、品牌和字体哪些保持，以及当前文字与动作怎样变化 |

“字体样张只供参考”目前已经存在，不能当成新修复。需要改的是**当前目标标题的一对一替换关系、品牌区独立性，以及对样张附带图形的职责解释**。是否需要改素材表达，另作实验；不直接修改原版字体库或付费回执。

## 五、当前输入字段怎样分工

尽量复用原结构，先收紧字段职责，而不是另写一套固定场景模板：

- `learner_story` 与 `art_direction.story`：保存整套内容依据、推进关系和分析，不整段无条件复制到每一张。
- `concept.prompt`：保留整套自由规划供记录，不直接放入新版套图的生图请求；`common_visual` 单独保存共同可见的场景和空间设定，不写后续动作或执行流程。
- `slot_actions` 各项（分别对应图1／2／3）：分别保存当前瞬间、动作、视线、支撑、机位与本张必要的变化。每张都要完整，不能只写“换成开心”。
- `style_id` 与具体角色画风适配：先冻结选择，再把当前需要的画法与适配交给绘图；身份保留与材料表现分别说清。
- `poster_prompt.compose`：只接收**当前这一张已选好的内容**和本次实际素材编号，编排分块提示词；不把整套自由文本当作当前画面任务。`positive_prompt`保留共享视觉规则与历史格式校验。
- 原确认稿、产品资料与补充要求原文继续留在输入中。规划时分配其适用范围；只把当前图片相关部分交给绘图，不要求用户为每张再填一遍表。

如需收紧规划输出的结构，可将“共同视觉设定／逐张画面任务”分别保存并验证；新字段应以减少混用为目的。**不对整个Prompt简单扫描或删除“第二张”等词**，用户确认文案本身可能合法包含这些字，应检查字段来源与用途。

## 六、以本次双图说明上下文切分

### 规划模型看到的整套资料

- 确认文字：图1“拍题精学”，图2“一拍就会”。
- 当前保存CTA为空；产品资料为空。
- 本套固定：小锤原型、折纸画风、字体27、当前横版版位。
- 共同视觉：统一的纸艺人物、道具和学习空间；品牌与标题字体各按自己的参考处理。
- 图1职责：让人看懂正在拍题，组织手机镜头与题纸的关系。
- 图2职责：给出与前图不同的理解／练习状态；不因文案概括就编造讲解视频、解析界面或成绩提升。
- 规划输出：分别说明两张的瞬间、机位、支撑、文字留白和保持／变化关系。

### 首图生图拿到的内容

创建一张完整横版广告；主标题“拍题精学”；当前拍摄瞬间；小锤身份如何纸艺化；具体空间、动作、机位和标题层级；原版Logo／IP／字体的实际参考职责。到这里结束。

“图2将引用本图”“图2的短句是一拍就会”“两张分别展示……”不作为这一张的执行要求。

### 第二张生图拿到的内容

唯一图像参考为本套本版位首图原始PNG；当前标题整体换成“一拍就会”；保持已经确定的角色身份、纸艺语言、品牌和字体体系；给出这一张明确的学习动作与适用机位，调整当前文字的断行与留白。

绘图模型会看到所传首图本身，但不能宣称额外的规划模型已视觉分析过首图。若没有实际图像分析能力或人工观察，不捏造“首图实际是什么姿态”的描述。首图明显偏差也不能被一句“全部保持”当成必须继承的正确约束。

完整的离线首图／分支草稿见[调研文档的改写示例](research/2026-11-02-multi-image-prompts.md#改写示例同一折纸方案保持原素材和原确认稿)。这些草稿尚未做付费出图验证。

## 七、恢复、重出与历史结果

| 操作 | 上下文要求 |
|---|---|
| 查询恢复／断线返回 | 保持原请求、原Prompt、原素材与任务回执，不能按新规则偷偷重新规划或提交 |
| 重出首图 | 使用本轮原版素材和当前首图任务；建立新图片版本，后续图只绑定新首图，历史文件保留 |
| 只重出图2／3 | 使用仍然有效的本套首图和当前分支任务，只改变用户指定部分，不重新随机身份、画风或字体 |
| 修改确认文案 | 先形成新的确认稿与制作轮次，不在既有某张Prompt里悄悄改变已确认文案 |

API Key、任务号、缓存路径、并发、费用授权、失败恢复、文件版本、像素和KB等继续由本机代码处理，既不需要成为创意提示，也不应泄漏到模型画面中。

## 八、实施时的验收准则

1. 单图原模板与输出合同先保持现状，作为回归基线；不要为了修双图而全局换掉已有效的单图写法。
2. 双／三图首图的文字与动作只来自当前图1；整套叙事与未来执行说明不进入首图。
3. 每次素材编号和用途与实际发送图片严格对应；分支不重新塞入Logo／IP／字体三张原图。
4. 身份、画法、字形、品牌各有明确职责，标题样张不会在计划里被当成完整Logo或完整广告。
5. 动作、视线、物体支撑和机位能同时成立；每张只有一个当前瞬间。
6. 后续图完整替换当前文案，有真正适合该句的状态变化；不只是换标题、不连带继承首图错误贴纸。
7. 固定同一套素材、模型、版位与确认稿，先比较原首图与新首图，再测分支；静态通过不宣称效果已经提升。
8. 不新增强制视觉复核表；仍由人预览、挑选，程序继续保障客观文件规格与依赖。

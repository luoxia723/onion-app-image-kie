# KIE 请求与恢复

实际生成入口为本机工作台。图片执行由 local_app/kie_client.py、worker.py 调用 scripts/render.py 的共享HTTP与回执函数；render.py 不再提供另一套独立制作命令。

模型与画幅由 scripts/kie_model.py 管理，当前注册GPT Image 2、GPT Image 2.5 Sunburst和GPT Image 2.6 Flare，均固定1K。新安装工作台默认沿用内部当前使用的Flare，已有配置和轮次不变。工作台保存轮次模型和请求指纹；变更模型建立新轮次，恢复查询不换模型。参考图按真实顺序上传并按内容缓存。

创建任务前落盘冻结请求的指纹和提交时间，收到任务号后持续保存回执。已知任务号的暂时查询失败或超时，普通出图、喜马拉雅、学习机和多尺寸适配都按 5、15、30、60 秒间隔最多续查四轮。续查复用原任务号，学习机在等待间隔释放图片并发槽。自动续查用完后可继续手动恢复。

本机未收到任务号时，图片显示「等待回执核对」。在 KIE 任务记录查到任务号后，输入并选择「接回任务」。服务端先用当前账号读取详情，并核对任务号、冻结请求及图片版本。旧回执缺少上传参数指纹时，核对模型、实际提示词、画幅、分辨率和提交时间。已确认未受理时，选择「确认未受理后重出」并确认提交。普通任务为重出保留旧版本，学习机在冻结的未完成记录上继续当前操作。

任务卡片、制作进度和图片详情使用后端判定的 `kie_recovery_action`。有任务号可恢复查询，有待核对的提交记录可接回或人工确认未受理。回执缺失或损坏且无法证实未发送时，页面提示核对 KIE 记录或恢复备份。普通任务重启时，仅在当前图片有发送前的进度记录、没有已知任务号和已下载原图时重新排队。学习机恢复必须读取已有回执，或使用明确确认未受理的记录。旧回执仍可读取历史任务号，正式执行仅使用手动重出和原任务续查。

返回链接失效时，使用 [KIE 临时下载地址接口](https://docs.kie.ai/common-api/download-url) 重新取图。个别网关不支持该接口时，回查[原任务详情](https://docs.kie.ai/market/common/get-task-detail)获取结果。取回的图片会校验并保存到本机。

如果系统环境的 HTTPS 代理指向本机回环地址，工作台在发送前为 KIE 官方 API `api.kie.ai` 选择直连。自定义接口和远端代理沿用系统路由。喜马拉雅同一首图的各分支逐个提交，回执保存后再发下一张，已受理的任务并行生成、查询和下载。进程重启后，普通任务恢复仍在执行且已有任务号的图片，学习机保留中断记录和回执供原任务恢复。

Keys保存在本机.env中，设置不回传明文，日志不输出Key。提交制作、重出和明确的AI背景调整属于调用API的动作；保存草稿、查看历史、本机裁切压缩、Logo换款和打包不新增生图调用。

启动、设置及交付说明见[本机工作台说明](../本机工作台说明.md)，任务行为见[工作台行为](workbench-behavior.md)。

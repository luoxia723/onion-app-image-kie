# 双图／三图提示词：官方资料核对与改写依据

日期：2026-11-02。研究范围是官方提示词与接口资料，不是付费出图实验。未调用语言模型、生图或素材上传 API，也未修改运行代码。具体故障归因仍需与本机已发送 Prompt、输入图片和实际输出逐项对照；本文不把静态检查通过当成视觉效果通过。

## 结论

“先生成第1张”解决了依赖顺序，却不保证首图优质。首图如果把字体样张当成完整贴纸、没有真正执行指定画风，后续图再要求继承首图，会有继续带入偏差的风险。**后半句是结合本项目用途的机制推断，不是官方对这批图片的诊断。**

官方资料支持的方向是：每个输入各有明确职责；精确指定当前画面的文字；编辑时区分保留与改变；先检查一个起始结果，再对后续变化做小范围迭代。它没有承诺把一张结果传回去就能自动修正其错误。[OpenAI 图像提示词指南](https://developers.openai.com/api/docs/guides/image-prompting)

## 1. 独立首图应写成当前这一张的完整任务

本项目业务合同已经要求每张是独立广告，图1用原版素材，图2／3只引用同套图1原始 PNG；无需为了研究改变这套依赖。[本仓库 SKILL](../../SKILL.md)、[渲染清单合同](../render-manifest.md)

建议保留以下信息，编排顺序不是模型的硬语法：

1. 当前要产出的**一张完整广告**及其版位和传播任务。
2. 本张确认文字、层级和位置；若 CTA 已配置，逐字写清按钮内容。
3. 主画风如何具体支配人物、道具、空间、线面和材质；品牌 Logo 和标题字体各按自身参考处理。
4. 一个当前瞬间：谁用哪只手做什么、道具如何支撑、视线落在哪里、机位能看到哪些证据。
5. 按实际编号逐张界定参考用途和保留项。

系列计划可保存在结构化记录中。首图 Prompt 没有必要展开“第二张／第三张将如何生成”的执行说明，更不应把其余张的动作要求写成首图当前瞬间的并行动作。这是为了消除职责歧义的项目建议，**不是“长 Prompt 必然更差”的结论**。

## 2. 带字字体样张应限定为字形来源

截图中角落旧口号与字体样张相似，符合“输入图的完整图形语义被带进成图”的表现，但单靠截图不能证明是唯一原因。主代理核对已证实单图和双图首图都已有完整字体替换条款，因此不能把本次问题写成“漏写 font_rule”。接下来更应看参考图中附带图形的竞争、整块样张与 Logo 的混淆，以及首图流程叙述和角色画风适配的影响。

以下是职责边界的表达示意；它不能被理解成“把当前已经存在的字体规则再补一遍就能修好”。可以在项目要求的一段正向自然语言中更直接地表达：

> 参考图3只提供标题的字形骨架、笔画粗细、描边层次与排版密度；本张标题内容完整替换为“拍题精学”，在指定主标题区呈现一次，作为画面的主要文字。参考样张中的原句、装饰贴纸与附带图形不构成本张广告内容。品牌区采用参考图1的原版 Logo，标题样张不承担品牌区职责。

这是针对当前“拍题精学”的**改写示意**，编号必须以实际请求为准。它不是通用固定场景，也不是对参考字体或 Logo 的重新设计。原仓库要求正向段落，不应为了防复制引入冗长负面提示段或新的内部文字白名单。

如果仍稳定复制旧口号，才值得单独研究字体参考素材是否需要更纯净的表现；那属于素材方案变更，不能直接改动本轮原版资产、回执指纹或已付费结果。

## 3. 指定画风与角色身份应分清保留范围

“角色沿用原图”容易同时携带原图的二维线稿、材质和上色；“整幅折纸／浮雕”又要求另一套表现。两者如何共存要写出具体分工，而不是各写一句后交给模型自行仲裁。以上为本项目中的冲突风险推断。

可以在既有业务许可范围内保留角色识别特征、主要服装和配色，让所选画风负责其造型表达、材质、人物与场景的统一；Logo 的图形、标准字与品牌色仍保持原要求。举例说，“纸艺”应具体到折面、折痕、纸纤维和空间塑形，而不只是把几只纸飞机摆在常规动漫人物旁。成图是否真正执行，仍要对照人物、主体道具、背景三部分看。

角色参考与画风之间不存在从公开文档可直接设置的“优先级权重参数”。不要把问题简单归因于 API 缺一个未经确认的权重选项。

## 4. 拍题动作必须能够同时成立

当前内容是拍题时，应先把手机、题纸、人物视线和机位组织成一个可见、可信的瞬间。一个可用于讨论的动作片段是：

> 学生右手持手机，让背面镜头朝向桌面题纸；左手压住平放题纸的一角。镜头从学生侧后上方取景，使侧脸、持机动作与题纸同框。屏幕朝学生，画面重点是手机与题纸的拍摄关系。

这是几何关系示意，不固定所有套图都用此场景或机位，也不补造产品界面与功能。若需要正面表情，就应重新安排设备朝向或拍摄角度，不能同时要求完整正脸、不可见的屏幕、背面相机和被身体遮挡的题纸全部清晰呈现。

## 5. 后续图应保留锚点，明确整体替换内容

在既定“图2／3只传图1 PNG”合同下，分支 Prompt 需要包含两个清楚的部分：

- 保留：首图实际确定的角色身份、画风表达、世界、品牌区和字体体系。不要把首图中已经出错的文字、动作也概括进“全部保持一致”。
- 改变：当前短句完整替换首图文案区；本张只描述自己的一个动作和叙事阶段；为新短句调整断行、字距及必要机位。

三图仍各自引用图1，不需要无依据改成图1→图2→图3。若首图存在文字贴纸或风格偏差，默认继承不能被当成纠错工具。这同时是三图的潜在风险，但**没有实际三图样本时，不能断言三图效果已经很差**。

首图实际姿态与最初计划不一致时，原通用规划 Skill 本就建议先看实际首图再写分支变化。是否在产品里采用先验首图、再批量分支，应遵循用户希望的批量效率，不重新加上强制视觉复核表。[本仓库画面规划 Skill](../../skills/visual-scene-planner/SKILL.md)

## 6. 下一轮怎么验证，才能知道改法是否有效

先固定模型、1K、版位、确认稿、IP、画风和同一字体样张，避免把参数和提示词同时变动。只选一套首图做分组比较：

1. 原 Prompt 和原素材，作为基线。
2. 只移除首图中“第二张参考本套首张”等后续执行叙述，保留其他内容。
3. 在2的基础上，只明确角色如何落实已选主画风，保留识别特征。
4. 在3的基础上，只强化“当前文字完整替换样张语义、字体样张不承担品牌区”的职责边界。
5. 在4的基础上，只修正手机—题纸—视线—机位关系。

分别记录旧口号复现、主标题准确性、人物／道具／背景的画风一致性、动作关系、品牌保真和主次层级。首图变好后，才用同一首图测试一次分支，观察当前文案是否完整替换以及场景是否产生必要变化。少量单次结果不足以证明稳定性；如果需要衡量成功率，应在用户授权的预算内重复难例。

这是建议的后续实验设计，不表示本次已经执行，也不是自动发起付费任务的授权。

### 已确认：先首图、再分支的技术顺序正确

- 六个双图分支均只含一个参考，路径为其同版位、同套图1的原始PNG。
- 这六张首图的实际PNG哈希均与保存的 `raw_sha256`、KIE下载完成回执一致。
- 十二张保存 Prompt 均与对应 `.job.json` 中交给 worker 的 Prompt 一致。
- [调度器](../../local_app/engine.py)在首图状态为done后才排入分支；调用前再次核对首图哈希。参考图没有误绑到别套，也没有用压缩JPEG代替原始首图PNG。

这些证据证明本地依赖和输入绑定，不能证明远端模型会正确理解文字与参考图。

### 已确认：字体样张与输出中的错误内容对应

| 方案 | 原样张 | 小米首图实际表现 | 小米图2实际表现 |
|---|---|---|---|
| 1 | 字体23：“点下，老师单独给你讲”，附蓝色吉祥物 | 左上出现同句旧口号和样张装饰，确认标题“拍题精学”另外排出 | 同一旧贴纸继续出现，主标题换成“一拍就会” |
| 2 | 字体27：“熬夜刷题，一题卡2小时？” | 没有在截图中明显复现该旧句，但人物仍以常规动漫绘制，纸艺只部分落在环境与道具 | 人物上衣出现一些折面，整体仍是混合表现 |
| 3 | 字体06：“作业卡壳别干等”，附对话气泡、闪电和长副文案 | 左上整块样张语义与装饰被搬入，品牌区与样张混在一起 | 旧样张继续保留，当前主标题独立替换 |

原图观察确认了“哪块素材被复制”，但没有做消融生图，不能把所有偏差单独归因于某一个输入。特别注意：**21/21单图首图和6/6双图首图都已包含 `font_rule` 完整条款**，其中明确写了示例字句应由本轮文字完整替换。[编排代码](../../scripts/positive_prompt.py)

主要修正对象不是“忘记写只参考字体”，而是把目标标题与样张建立一对一的替换关系、消除样张兼任品牌贴纸的解释空间；若纯文字改写仍失败，再另行讨论素材表示方法。

### 已确认：首图混进了后续请求的流程说明

六张双图首图的 `concept.prompt` 都包含“第二张参考本套第一张完整广告成图……”。这个共享概念段被直接拼入首图 `base_prompt_rule`，再拼入本次生图 Prompt；单图21张里没有这类后续请求句。

可复现的只读检查结果：

```json
{"double_first_images":6,"first_prompts_containing_future_request_instructions":6}
```

本次诊断命令断言“首图不应含后续请求说明”，以断言失败稳定复现。该检查证明职责混杂，不量化其独立的图像质量影响。修正应在计划字段职责与编排层完成，不对用户确认文案做关键词删句。

根因路径：[规划输入与约束](../../local_app/scene_planner.py)让模型一次规划整套，但没有单独限定共享 `concept.prompt` 为纯共同视觉设定；[视觉方向编排](../../scripts/visual_directions.py)将整个概念段加入首图。这与[原APP适配要求](../scene-planning-app.md)中“共用场景段不预写所有阶段”的意图不符。

### 已确认：正向格式丢掉了现成的角色画风适配信息

`assign_styles` 对正向格式把 `ip_adaptation` 设为空；`plan_content_concepts` 的正向路径没有追加专门的IP画风适配，旧格式路径却有。[具体代码](../../scripts/visual_directions.py)

而[原风格库](../../config/visual-directions.json)已有针对性说明：折纸角色要保留身份并用纸面绘制细节表达五官；刻纹风格要用细刻线表现脸部等。本批实际首图没有这些具体适配句，只在开头说通用材质、后面又强调角色外观沿用原参考。

这使“角色身份保持”容易被模型解释为“沿用参考动漫渲染”，与“人物和环境统一纸艺／浅浮雕”发生竞争。原图中人物与背景材质分裂支持这个诊断方向，但该编排缺口也存在于单图，不是双图独有缺陷；改善幅度需要生图对照确认。

### 设计诊断：拍题关系和学习证据不足

方案3首图同时要求手机背面朝题页、观众看见题页夹正面和手机背面、并从人物侧前方拍摄，几何关系很吃紧。现有图中手机更像被随手举起，而不是清晰执行拍摄。这里是根据实际构图做的设计判断，不能用静态字符串校验代替。

图2的规划把“一拍就会”落为“手指指着题纸”，手机放在旁边，没有更明确的理解／练习变化。第二张虽换了动作，却不一定更清楚地表达产品帮助。因为当前产品资料为空，不能直接编入视频讲解、自动生成解析、提分等未提供的功能；后续应利用已有确认事实，或将其控制在拍摄、理解和练习的可见状态内。

### 三图边界

本机没有本任务的真实三图轮次。[轮次构建](../../local_app/planning.py)与最终编排对双图、三图复用同一套首图／分支逻辑；三图的图2、图3均引用本套图1，故共享这些风险，但本次没有三图实际质量结论。

## 改写示例：同一折纸方案，保持原素材和原确认稿

以下是离线设计草稿，用当前原编排器生成，并通过现有单段格式、文案、字体、Logo和分支替换的静态合同校验。**没有调用模型，尚未验证出图提升。** 本例保持小锤、折纸风格、字体27、相同版位、图1“拍题精学”、图2“一拍就会”和空CTA；不改成固定场景池。

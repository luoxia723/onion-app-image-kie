# 视觉与 Prompt 规范

本文件是 APP 图片 Prompt 的规则 owner。它把当前洋葱投放单图 Prompt 的创意方法迁移到本地 APP 图片流程；本地配置卡、KIE、选择页和不写飞书的边界由 SKILL.md 负责。

扩展风格、字体或布局前，先读[固定项清单](visual-invariants.md)，区分品牌与渠道约束、当次配置及可探索项。风格词或外部参考不能覆盖固定项。

## 1. 先建立最小创意链

Prompt 属于 Creative Path，不能只把文案和“学生学习场景”拼在一起。写 Prompt 前先整理：

~~~text
功能事实 → 目标学生 → 具体场景 → 学习阻碍/情绪 → 产品动作 → 可感知变化
~~~

临时文案入口至少完成 Lite 版本：

- 文案锚点：主标题、副标题、CTA（如有）；
- 目标学生：默认学生，除非本轮明确指定其他人群；
- 学生正在经历的具体时刻；
- 他卡在哪里、为什么没有继续；
- 产品在这一帧里具体做了什么；
- 画面让学生感受到什么变化。

产品动作必须来自 产品资料/ 或用户本轮明确提供的事实。例如拍题精学只能使用资料中确认的拍题、分步骤解析、步骤讲解、继续追问等动作；不能把其他功能的规划、诊断、课程或服务动作混进来。

## 2. 单图必须在一帧里讲清楚

单图的目标是让学生在 1—3 秒内看懂：

- 这是自己的学习痛点；
- 洋葱具体提供了什么帮助；
- 画面从“卡住”走向什么可感知变化。

单图 Prompt 至少包含：

1. 具体场景和瞬间，不写泛泛的“学生在学习”；
2. 学生、IP 或工具的动作；
3. 产品动作或产品证据。没有真实 UI 截图时，不编造可识别 APP 页面，可以用纸面步骤、抽象卡片、光效、动作关系或不可读屏幕表达；
4. 图片中的完整中文文案；
5. Logo、IP、字体和风格参考图的用途；
6. 构图、文字层级、色彩、光线、质感和安全区；
7. 禁止项、合规边界和“直接新图”声明。

有 IP 时，正文先确定统一的视觉体系（例如高质量动漫插画、半写实广告合成感或软萌 3D 卡通），再让学生、IP、场景和道具处在同一体系内。IP 第一次出现时写明“某 IP（参考图N）”。文本主导方案可以不用 IP，不为凑角色强行加入。

## 3. Prompt 结构模板

不要求每次使用完全相同的段落顺序，但必须覆盖以下信息：

~~~text
参考图说明：参考图1是……；参考图2是……；参考图3是……。
[渠道语境和画面任务]：信息流/应用商店/学习机的单图语境，以及画面要完成的沟通任务。
[场景与产品动作]：学生处于什么具体时刻，哪里卡住，产品或 IP 做什么，变化如何被看见。
[文案与信息层级]：逐字写出主标题、副标题、CTA；说明位置、字号层级、留白和可读性。
[视觉体系]：人物、道具、构图、颜色、光线、质感和节奏。
[资产约束]：Logo/IP/字体/UI/风格参考图各自的使用边界。
[生成和禁止项]：首张直接生成新图；同套分支按下文SAME/CHANGE描述状态变化。不使用外部旧广告图，不编造UI或未确认事实。
~~~

文案必须逐字保留，不能让模型自行改写核心事实、删掉必要补语、添加价格、数字、按钮或效果承诺。

## 4. 尺寸参数不写进 Prompt 正文

比例、像素、出图尺寸、目标尺寸和 KB 上限是配置卡与工具参数：

- Prompt 正文只写“竖版信息流广告海报”“横版应用商店单图”等构图语境；
- render.py 的 size、导出尺寸和压缩目标只从 image-config-result.json 的 placements[] 读取；
- 生图使用Sunburst 1K固定比例，最终交付像素保持渠道要求。预计常规裁切达到6%（含6%）时，按[白底蓝框适配](blue-frame-adaptation.md)先生成布局参考，整张广告只生成在框内、框外纯白；OpenCV去框后拉伸至目标尺寸，生成后由用户查看效果。低于门槛常规适配；
- 不要在 Prompt 正文写 720x1280、1080x1920、9:16 或 800KB，避免把制作参数误当成画面内容。

白底蓝框模式替换旧的百分比边缘留白段和“背景铺满整张画布”要求；背景只铺满框内。范围规则由`scripts/blue_frame.py`生成，不自行编写不同坐标或同时叠加旧留白。

## 5. 参考图顺序和字体规则

完整参考图的默认顺序：

1. Logo；
2. IP；
3. 白底蓝框（命中适配分支时），然后是其他风格/构图参考（如果本轮选择）；
4. 字体参考；
5. 真实 APP/UI 截图（只有画面确实需要可识别 UI 且用户已上传时）。

以上顺序用于单图及同套首张；分支只使用同套首张PNG作为参考图1。实际没有选择某类资产时跳过该类，后续编号顺延。Prompt 中的“参考图N”必须与 reference_images 数组顺序完全一致，首张素材路径来自本Skill的assets/asset-manifest.json、本轮用户上传的真实文件或脚本生成的蓝框布局；分支路径必须是清单中同套图1的output。

选择 Logo 时，由 AI 随画面直接生成，使用所选原版 Logo 参考图。位置默认左上角；**喜马拉雅 720×1280、720×1559 两种竖图是例外，必须上方居中，不能放左上角**。按已保存配置调用 `scripts/logo_reference.py` 的 `logo_position(config)` 确定位置，再用 `logo_prompt_rule(label, position)` 生成保真约束；其余保真要求保持一致，不增加 Logo 叠层预配置流程。

默认位置的“参考图说明”原文：

> 左上角原样呈现参考图1的完整 Logo，图形、文字、颜色、比例、轮廓及角标均与原图一致，不得重绘、变形、简化或拆分；Logo直接融入画面原有背景，周围延续整体色调，不另加底板、色块、边框或弧形区域，仅调整整体大小和位置。

上述两种喜马拉雅竖图将开头的“左上角”替换为“上方居中”，并在构图说明中明确 Logo 水平居中、靠近画面上方、保持完整与适当边距；同一 Prompt 只保留一个位置指令。AI 生成不能保证与原版像素级一致，检查偏差后由用户选择采纳。

前景与局部背景的对比要求适用于任何配色：Logo、需阅读的文案及需识别的关键图形，在最终交付尺寸下都必须清晰可辨，不因前景与背景的颜色或明度过于接近、纹理干扰或遮挡而丢失。深色压深色、浅色压浅色、近色叠加造成识别困难时，都要调整；不是只检查某一种文字颜色，也不是机械禁止同色系搭配。辅助背景和装饰可以降低对比以突出重点，不要求所有元素同样抢眼。

发生冲突时，优先调整局部背景、自然留白和布局；普通文案可在字体参考允许的范围内调整色彩。Logo仍保持所选原版颜色，不临时换色、加描边或另加独立底板；应按该版本Logo的实际前景颜色选择合适背景。该项需写入当前Prompt并在目标尺寸预览中检查，目前没有自动前景／背景可读性质检。

字体启用时，每套选一张洋葱字体参考PNG，仅传给首张；同套分支从首张继承，不能重新随机或重复传入。首张Prompt写清：

- 参考图N只用于字体气质和排版参考，不复制参考图示例文字；
- 主标题优先遵循参考图N的字形骨架、笔画粗细、转折、外轮廓、描边层级、字面宽窄和排版密度；
- 不要擅自改成另一种书法、手写、卡通、贴纸或渐变字体类型；
- 颜色可以根据当前画面调整，文字必须保持清晰、完整、可读。

这些 PNG 是风格参考，不是真实字体文件；不能承诺像素级复刻。若用户要求严格一致，必须先补充已确认的真实字体文件或确定后处理方案，不能只靠 KIE Prompt 保证。

## 6. 参考图和 UI 门禁

- 用户上传的 Logo、IP、字体或风格图是本轮直接生图参考，不是旧广告图迭代基准；
- 旧广告图、G-ID、同款扩图、换文案保留原风格等需求不进入本 Skill；
- 如果画面有手机、平板、电脑、学习机或其他屏幕，并且屏幕要展示可识别的洋葱 APP/学习 UI，必须先拿到真实截图并将其作为参考图；
- 没有真实截图时，屏幕只能弱化、模糊、偏转、过曝或显示不可读抽象内容，不能写具体页面结构和虚构功能。

## 同套双图三图生成

- 图1是base，传Logo/IP/字体等本轮原版素材，逐字使用短句1。图2和图3均以同套图1为基础做delta，各自只使用短句2或短句3，替换首张主文案并改变相应动作、情绪与学习状态。
- 分支清单填写`base_job_id`，`depends_on`必须且只能包含同套图1的job_id。`references`仅包含图1的原始PNG，编号为参考图1；不重复传Logo/IP/字体，不引用图2来生成图3，不引用其他套首张。
- 分支SAME：人物身份与服装、视觉体系、场景连续性、字体气质、色彩、Logo内容与位置、文字层级。CHANGE：本slot确认文案、服务该文案的动作/表情/任务或进度状态。不得把首张文案保留成副标题，不新增辅助文字。
- 每张job保存`copy_text`，必须等于本slot确认短句；Prompt使用`scripts/series_chain.py`的`text_rule`生成文字白名单。只允许对应短句、已选Logo标准字和已确认CTA。不要把另一slot的品牌词或示例口号写成必需保留文字。
- 付费前先校验整套文案、分支依赖和未来参考路径；首张尚未生成时只延后文件字节校验，不用占位图替代。首张落盘后核对其PNG、SHA-256和任务回执，再对分支运行render校验并提交。默认顺序执行，恢复时复用原任务，不重新提交已完成图片。
- 蓝框版位的分支使用带框原始首张，继承同一个`frame_layout_path`。分支写入`blue_frame.prompt_rule("参考图1")`，保持框线位置和框外纯白；后续仍按原蓝框规则去框。
- 模型内容偏差仍记录候选提示，不自动增加付费重做；本规则不会保证Logo或文字像素级保真。

## 7. 多套直接生图的差异

同一套先确定视觉体系，不同套主动错开。按[多样化编排](visual-directions.md)从风格、布局、镜头、场景和配色选择本轮方向，写入visual-plan.json并绑定实际Prompt。

- 多样化优先扩展主风格本身。每套只定一个主风格，不同套优先使用不同的主导视觉语言；配色、光影、布局和局部材质是辅助选择，不把它们的组合数当作主风格数量。

- 默认开放编排：Agent根据当前文案与动作编写本轮风格候选，按主导画法/媒介、兼容材质、光影和空间组织形成具体方向；可加入新的构图和镜头。现有预设只作示例与补充，不限制风格总数。不同套优先同时改变画法与构图，仅换颜色、换IP或镜像不算充分探索。
- 用户指定的IP身份、Logo、确认文案、真实UI、渠道及字体要求优先。IP的画法、材质和光影可适配整体风格，但脸型、发型、体型、服装及关键标识保留；Logo保持原版，不应用风格化重绘。
- 字体仍按每套选择一张原版参考，不能因水彩、纸艺、印刷等场景风格擅自变成另一种字体。Logo也不跟随普通标题字变化。
- 同套图2/3只引用图1，继承其风格和布局，按各slot文案改变状态；不为追求多样化让一套里的三张各用一种风格。
- 用户明确要求统一风格或布局时遵从本轮选择，不为去重覆盖用户意图。用户固定项通过visual_direction保存；Agent本轮开放候选通过visual_candidates保存，优先使用本轮候选，不要求用户逐一命名风格。
- 池中方向是Prompt编排选项，不代表模型效果已经逐项实测。内容检查与候选选择仍按现行合同执行。

## 8. 生成前自检

付费前逐张检查：

- 每张copy_text、文字白名单和提示词是否只包含对应确认文案，是否有跨slot文字冲突；
- 功能动作是否来自产品资料；
- 是否在 1—3 秒内看懂痛点、产品动作和变化；
- 参考图标签、顺序、asset_id 和路径是否一致；
- 字体参考是否真的放进 reference_images；
- 是否把尺寸参数留在工具参数而不是 Prompt；
- 是否出现虚构 UI、风险承诺、竞品品牌或旧图继承指令；
- 是否按配置卡的版位、Logo、CTA、套数和 UI 门禁执行。

## 9. 生成后只提示，不拦截候选

本文件只负责提高Prompt质量，不承诺模型逐项机械执行。生成后的候选提示、继续生成和人工选择规则统一遵守[输入、输出与人工门禁](input-output-contract.md)，本文件不重复定义。

# 视觉与 Prompt 规范

本文负责最终生图Prompt的写法。[固定项](visual-invariants.md)依然生效，但应在合适的执行层落实，不能把所有制作规则都塞进模型提示词。

## 创意先定调，再落成画面

按[艺术定调](art-direction.md)先定画风，再定世界与场景、故事瞬间、构图与阅读路线、光色与材质。内部整理“功能事实→学习处境→产品动作→可感知变化”，产品动作来自当前确认资料。将这些决定融成具体画面，每张都有学生或选定IP，通过姿势、视线、表情和学习行为表达当前文案。学习者、具体痛点、产品帮助和可见变化记录在visual_concepts.learner_story中。

批量默认按套随机主画风，优先不重复；单图每张是一套，双/三图套内统一。其余视觉维度根据画风整体设计。古代、中世纪、现代、未来与幻想场景均可使用。单图在一帧里表达一个清楚的瞬间，双/三图按短句推进同一故事。设计细则见[完整画面方案](visual-directions.md)。

## 最终是一段正向自然语言

新保存配置使用`prompt_format=positive_paragraph_v1`。最终Prompt保持一段话，用自然语句连起画风、场景、动作、构图光色、确认文案与必要的参考用途。参考说明可穿插在相应元素旁；不添加章节标题、列表、JSON文字清单、内部方案编号或negative_prompt。描述希望出现的内容，不列举不要出现的元素；也不补写“无IP”“无屏幕”等排除声明。用户确认的广告文案逐字保留，即使文案自身含“不”等字，也不能机械过滤。

沿用之前的画面叙述方式，将新增设计层级完整整合进去。以说明清楚、约束完整、能够执行为优先，不设置首张或分支的默认字数目标，也不机械截断。人物、场景、痛点、产品帮助、文案层级和适用的视觉约束都应写清楚；内容多时自然加长。只合并重复表述，不为缩短而删减必要信息。

例如一段话依次自然交代：采用何种画法、在哪里发生什么、这一张的具体动作、视线与标题如何连接、完整主副文案、实际参考图的用途。参考[一段式示例](prompt-examples.md)。

## 原始格式与文字标记

最初版本以“参考图说明→场景与产品动作→文案与信息层级→视觉体系→资产约束”组织信息，其中文案明确包括主标题、副标题和已配置CTA，并分别说明位置、字号层级与可读性。当前保留这些职责，合并为用户要求的一段正向自然语言；艺术定调只增加有用的画面决定。

画面文字用引号界定原句，例如“主标题文字为‘这周我想把数学补起来’”。【主标题】或[文案与信息层级]是可供人阅读的标签，不是模型权重语法；默认最终Prompt直接使用自然语言字段说明，不向已确认原文添加装饰括号。用户原文本来含有括号时逐字保留。

视觉强调通过具体排版表达：第一文字层级、字号关系、位置、对比和留白。某个词需要突出时，描述该词的具体字号或配色关系，不靠包裹符号代替排版决定。人物场景选择一个可见的瞬间，用表情、视线、手部动作与题页、屏幕的关系表现当前痛点或推进。

CTA从保存配置的cta字段读取。非空时明确画成按钮，逐字使用按钮文字，并交代底部位置、对比和与人物文案的间距；同套每张继续使用确认CTA。配置为空时不额外添加按钮。新配置保存cta_render_mode=button，付费前校验完整按钮指令，不能退化成“行动文案呈现”一句普通文字。

这类文字边界与排版描述也符合[OpenAI官方图像提示指南](https://developers.openai.com/cookbook/examples/multimodal/image-gen-models-prompting-guide)的建议；对当前KIE配置的实际效果仍需以成图复核，不将某种括号写法宣称为已验证的增强机制。

## 规则放到合适的层

| 执行层 | 内容 |
|---|---|
| 配置与代码 | 固定模型和1K、比例与像素、KB与格式、蓝框阈值和坐标、引用标签与路径、原版素材绑定、同套依赖、费用与授权、任务回执和恢复、导出与选择流程 |
| 计划与清单 | 五层艺术定调、功能事实依据、确认文案、IP与字体选择、屏幕模式及界面用语、逐张动作和方案绑定 |
| 最终Prompt | 具体画面、需要可见的完整广告文案、素材的视觉用途、原版Logo保真与位置、角色识别、字体特征、必要的蓝框生成范围 |
| 成图检查 | 错字、Logo和角色偏差、可读性、画风与故事是否成立；按现行候选流程记录 |

代码能检查路径和文案字段，却不能保证模型把字画对。最终Prompt仍需逐字给出本张文案；原版Logo、字体、IP和框内范围是影响成图的视觉指令，用正向描述完整保留；精简措辞不能删除图形、标准字、原色、比例、轮廓、眼睛与角标等品牌限制。尺寸、压缩、代码裁框、文件哈希或授权说明不进入Prompt。

## 必须进入最终Prompt的七类视觉约束

原始分工保持不变：代码检查输入与执行，AI按Prompt绘制画面，成图另行复核。把约束保存在JSON或校验素材路径，不能代替下列绘图指令。`positive_prompt.compose`将适用要求各写一次，保持一段正向自然语言：

| 必要点 | 最终Prompt的执行要求 |
|---|---|
| 字体参考用途 | 仅取字形与排版特征，示例字句在当前画面由确认文案完整替换。 |
| 完整字体体系 | 保持字体类型、字形骨架、笔画粗细、转折、外轮廓、描边层次、字面宽窄和排版密度；插画画风用于人物和场景，标题仍用确定的参考字体体系。 |
| Logo背景处理 | 完整保留原版图形与全部标准字；周围共享整幅画面的连续背景，独立边界限于原版标识自身，描边和附属元素沿用原图。 |
| 可读性处理顺序 | 局部对比通过背景明度、自然留白和布局调整解决，装饰服从阅读焦点；Logo自身的原色和轮廓保持固定。 |
| 渠道与独立单幅 | 明确横版、竖版或方版及应用商店、信息流、学习机等用途；每次生成的是一张连续完整场景的独立广告图。数字比例、像素与KB继续留在代码。 |
| 事实与文字边界 | 广告正文使用本张确认文案，界面功能、说明文字与具体数字依据本轮确认资料。learner_story中已确认的product_action同时传入实际Prompt，作为产品帮助的绘图依据，不能只留在计划JSON。允许清晰示意UI，不改变这项事实要求。 |
| 分支保留与替换 | 首张文案所在区域整体换成当前短句，文案区仅保留本张确认内容；场景、人物、Logo与字体体系继承首张，断行和间距适应新短句。 |

新保存配置带`visual_contract_version=visual_rules_v1`。付费前校验适用规则已进入最终Prompt，包括字体开关、参考用途与分支替换要求。历史配置没有此版本时保持原Prompt与回执可恢复。静态检查证明指令被传入，不代表模型已逐项正确绘制。

## 参考图与视觉保真

单图和首张参考顺序为Logo、IP、蓝框（命中时）、其他风格/构图、字体、真实UI；未选类别跳过，编号顺延。实际参考标签、asset_id与路径由代码校验。分支仅引用同套首张原始PNG作为参考图1。

### 参考图用途与风格来源

画风在写Prompt前选定：默认从77条风格库按套抽取，指定画风时使用指定项。Prompt直接写实际画风名称和必要的画法特征，由这些描述确定整幅视觉体系。Logo图提供原版标识，字体图提供标题字形，两者各自承担对应的素材用途。

| 请求 | 实际参考图示例 | Prompt需说明 |
|---|---|---|
| 无IP单图或首张 | 参考图1=Logo，参考图2=字体 | “以透明水彩画风呈现……”；“参考图1的原版Logo……”；“参考图2用于标题字形参考……” |
| 有IP单图或首张 | 参考图1=Logo，参考图2=IP，参考图3=字体 | 写明已选画风，再分别说明Logo、角色原型与标题字体用途 |
| 同套第2、3张 | 参考图1=本套第1张完整广告成图 | 写明本套实际画风，以及“参考图1为本套已生成的第1张完整广告成图”，从该成图保持套内视觉连续性 |

上述编号仅作示例，实际以每次请求的references为准；蓝框等素材加入后编号相应顺延。首张才引用Logo、IP、字体等原版素材；分支参考图1是完整广告成图，含首张已落实的画风、场景与资产呈现。不要只写“参考图1的风格”而省略它的实际身份。

除主画风外，启用字体且本套未指定时随机选字体PNG，选择随机IP且本套未指定角色时随机选IP；均在最终Prompt编排前确定。时代与场景、故事、动作、构图、配色、光线和配饰由Agent整体设计，不单独抽签。Logo与确认文案等固定项按配置。

Logo位置调用`logo_position(config)`确定：喜马拉雅720×1280、720×1559为上方居中，其余默认左上角。调用`logo_prompt_rule(label, position)`得到正向保真描述：

> 左上角原样呈现参考图1的完整Logo，品牌图形与包含“洋葱学园”的全部标准字作为同一完整组合呈现，原版颜色、图文比例、轮廓、眼睛及角标逐项保持一致；以原版整体等比缩放与定位。Logo周围与整幅画面共享连续背景，独立可见边界仅由原版标识自身构成，描边与附属元素逐项沿用原图，完整标识清晰可辨。

在实际画面中选择与原版Logo颜色有足够对比的背景和留白。标题、Logo和关键图形在目标尺寸下均应完整清楚；辅助纹理与装饰服从视觉焦点。模型生成不保证像素保真，成图仍需查看。

字体启用时每套使用一张原版字体PNG，仅传给首张，分支从首张继承。参考图仅提供标题字形与排版，其示例字句由本轮确认文案完整替换。标题保持字体类型、字形骨架、笔画粗细、转折、外轮廓、描边层次、字面宽窄和排版密度，文字配色可随画面调整；插画画风变化与确定的标题字体体系分别管理。字体PNG是风格参考，严格字形复现需要真实字体文件或后处理方案。

有IP时保留脸型、发型、体型、年龄、关键标识及原服装核心配色与轮廓；在场景描述中选取少量对应时代或画风的披肩、扣件、纹样、材质或配饰。无IP时每张使用普通原创学生；有IP时选定IP承担人物叙事。每张明确人物在何种学习处境下做什么、什么表情、产品动作如何对应当前短句。物件和建筑用于强化场景与痛点，不代替人物参与。无IP学生按画风自然设计。

屏幕的conceptual/reference/none模式和`screen_text`保存在计划中，job的`ui_text`与计划一致。需要示意UI时正向描述其清晰内容；真实界面按实际截图参考呈现；不需要屏幕的方案直接描述其主体与道具。功能真实性与示意来源在资料和质检中管理。

## 同套双图三图生成

图1使用原版Logo/IP/字体等素材和短句1。图2、图3分别从同套图1原始PNG继承画风、场景、人物外形与服饰、字体和完整Logo，首张文案所在区域整体替换为本slot短句，文案区仅保留当前确认内容，同时推进动作、表情或任务状态。分支用正向的一段话说明继承内容、当前动作及替换后的唯一主文案。

清单中每张保存`copy_text`，等于对应确认短句；单图保存主副文案以换行连接的值。代码比对文案字段与Prompt中的原句。界面用语另存`ui_text`，无需写画面文字清单，也不调用旧`series_chain.text_rule`。

分支填写`base_job_id`和仅包含同套图1的`depends_on`，唯一参考路径等于图1的`output`。付费前检查整套覆盖、文案、素材、动作与未来路径；首张落盘后检查PNG、哈希及任务回执。恢复复用原任务。蓝框分支继承同一布局，使用`blue_frame.prompt_rule("参考图1")`的正向范围描述；坐标、去框与缩放由代码负责。

## 编排与检查

推荐调用`scripts/positive_prompt.py`的`compose(config, direction, slot, references, frame_label)`，由计划、实际素材标签和确认文案合成一段话。Agent负责先写好正向的场景和动作；编排函数不会用关键词删句，也不会自动截断。`frame_label`仅在实际命中蓝框时传入；单图/首张用布局图标签，分支用参考图1。

每张完整Prompt单独设计并保持不同。生成前核对当前文案、确认功能、艺术定调、素材用途和逐张动作是否吻合，避免把内部制作资料带入画面。`direct_batch.py --validate-only`做静态预检，不发起付费请求。

历史配置缺少`prompt_format`时按原计划和原提示词恢复，旧文字规则仅用于兼容历史回执，不注入新任务。生成后的候选检查、人工采纳和交付继续遵守[输入输出合同](input-output-contract.md)。本轮格式调整不代替实际成图验收。

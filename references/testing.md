# 测试说明

自动测试验证本机行为、文件合同和离线请求，不以通过数量代表实际生图效果。测试维护记录见[交叉审核记录](test-audit-2026-11-13.md)。

## 运行

在仓库根目录安装 `requirements-dev.txt`；前端检查需要 Node.js，运行应用不需要 Node.js 或 npm 依赖。

```sh
# 当前行为与前端
.venv/bin/python scripts/check_workbench.py
# 当前、历史、离线传输与前端的完整回归
.venv/bin/python scripts/check_workbench.py --suite all
# 指定分组
.venv/bin/python scripts/check_workbench.py --suite history
.venv/bin/python scripts/check_workbench.py --suite transport
# 查看当前实际收集范围；core/all还列出将执行的前端文件
.venv/bin/python scripts/check_workbench.py --suite all --collect
```

单文件或小范围检查可以直接用 pytest。`pytest.ini` 默认选择 `core`；指定历史或传输文件时需显式覆盖选择表达式：

```sh
.venv/bin/python -m pytest -q tests_local/test_learning_prompts.py
.venv/bin/python -m pytest -q tests_local/test_learning_workflow.py -m history
.venv/bin/python -m pytest -q tests_local/test_kie_transport.py -m transport
.venv/bin/python -m pytest -q tests_local/test_natural_canvas.py -m ''
node --test tests_frontend/*.test.cjs
```

Windows 使用同一虚拟环境的 `.venv\Scripts\python.exe`。`check_workbench.py` 会自行枚举前端文件，不依赖 shell 展开通配符。

## 主分组

| 分组 | 内容 | 分类依据 |
|---|---|---|
| core | 当前配置/API/提示词、任务与草稿、PNG/JPEG实际规格、队列/版本/交付/维护、共享脚本有效入口 | 未标记测试默认归入core；也可显式标记 |
| history | 已保存旧格式的文案模块、素材身份、规格、读取、备份恢复和交付 | 函数或模块显式 `pytest.mark.history`，不按函数名猜测 |
| transport | 生产供应商适配器对本机HTTP桩的上传、创建、查询、下载、过期链接和恢复行为 | 显式 `pytest.mark.transport` |
| all | 上述所有Python测试，加前端 | 覆盖默认过滤表达式，真正收集全部 |

一个测试只有一个主分组。当前入口拒绝旧模式属于core；验证旧记录仍可读属于history；在测试进程内使用本机API不自动等于供应商transport。目录名字或文件年龄不决定是否应保留测试。

旧背景v1提示词、旧基准场景序列化、缺少尺寸策略的旧裁框、没有独立图层的旧Logo导出，均显式放入history。它们保护冻结请求与已存图片，不参与默认core。当前的背景修补、强制重试、换Logo及恢复查询即使使用旧图片作输入，仍是可达业务动作，保留core；不能仅凭fixture名称含legacy就整文件移走。

旧模型Logo的位置、完整字标提示词及Logo素材请求也归history：新普通任务由`brand_logo`冻结独立图层，给模型的是无Logo底图要求，不上传Logo素材；旧validator仍用于已保存请求的验证与恢复，保留其兼容测试。当前图层的真实像素合成、Logo换款、底图哈希、旧ZIP和备份恢复继续在core测试，不将全部Logo测试一并移走。

关闭的旧36版位制作流程不再测试“如何新建其规划队列”。已移除只重建首模板/最大封面/六个派生子图的三个case；旧文案模块、真实PNG、备份恢复、来源版本与哈希的读取保护继续保留。

旧学习机母图直出的前端交互、OCR、版式样图 URL 和独立生图命令的辅助函数已清理。回归继续检查旧草稿按现行入口打开、旧提交入口拒绝执行、历史图片与备份可读取，以及当前的概念图上传正常。

## 共用母版的测试责任

| 测试层 | 应证明的行为 | 不应冒充的结果 |
|---|---|---|
| `test_master_canvas.py` | 同剧情同文字才能共组；模型原生比例、共同保留区、遮罩可见区、8%–12%安全余量；一张完整原生结果可裁出多种精确尺寸且不拉伸 | 合成图片几何通过不等于模型已生成自然画面 |
| `test_master_canvas_support.py` | 来源图、当前版位、正文/副标题/CTA、模型与图层规格在创建时冻结；不同剧情来源不混合 | 从当前对象互相比较不能代替来源不可变验证 |
| `test_master_canvas_runtime.py` | 执行一次母版请求供多张PNG/JPEG导出；成组重试、幂等和不确定状态恢复；原图、旧版本及图包保留 | 多个输出不应被计成多个必需图片请求 |
| 现有Logo/自然背景回归 | 换款复用最终无Logo底图，不反复裁切或生成背景；当前支持协议沿原指纹恢复 | 旧图没有图层来源时不能声称可以无损换Logo |
| 普通自然画布 | 全部普通版位使用无框输入，安全区、固定窗口、精确尺寸、原图保护和错误比例拒绝 | 图片内容未被语义检测，不能伪称人物完整性自动通过 |

共用母版的新构图草稿须画满原生画布，模型生成完整自然背景后，每个输出只按冻结裁框处理一次。原有学习机自然背景节点与显式修补入口仍有自己的可达调用链，不能把这些测试和新shared批次的一母多裁混为一条流程，也不能沿用固定旧调用次数判断新批次。调用数量应核对实际分组和执行记录。

## 隔离与替身边界

- 根 `conftest.py` 清除继承的供应商Key/执行模式等环境变量，阻断外部URL、DNS和socket连接，仅允许回环服务。`tests/conftest.py` 只给共享脚本提供明显的假Key和本机桩地址，不重复维护网络守卫。
- `Settings` 测试显式传临时状态目录与临时env文件；不加载用户 `.env` 或正式 SQLite。需要图片时用临时合成PNG、保留的测试素材或受控HTTP响应，不调用图片模型。
- `FixturePlanner` 是语言模型请求边界的离线替身；后续真实编译、依赖、文件处理和交付逻辑仍执行。用假函数替换被测逻辑本身不能证明该逻辑正确。
- 前端通过 Node `vm` 加载真实模块，初始化网络入口由共享helper抑制。request、DOM和render边界可替身；轮询安装任务、维护提交、选择版本等目标函数实际运行。
- Node测试可以验证请求、状态、输出HTML与几何计算，不能证明浏览器绘制、点击命中或视觉还原。布局与图片效果修改仍需在独立验收环境查看实际页面。

## 预期与回归要求

喜马拉雅套图回归使用普通调度器和文件导出，替换供应商边界。覆盖五尺寸整套、取消方图后由已选横图先审、其他信息流版位独立生成、同一首图版本的扩展、单尺寸重出及单套和混合图包。前端检查投放版位内默认全选和逐尺寸取消、混合成品目录、当前版本验收及导出范围。

整套审核回归覆盖逐图选中、全选与取消全选、选齐当前版本才开放整套导出。学习机 HTTP 和喜马拉雅打包检查空选择及重出后旧版本不可通过，已导出的历史包仍可读取。

逐张 Logo 验收回归检查普通图片和学习机 HTTP、喜马拉雅依赖与多尺寸 JPEG 输出。覆盖旧学习机仅冻结一款素材时的本机换色、预览与新图包字节一致、无 Logo 版位与过时请求受保护，以及切回后还原原成品。旧图包继续可读，合成期间没有新增图片模型调用。

成品网格由响应式 CSS 排版。原来针对已移除计算逻辑的模拟几何测试已清理。浏览器验收检查首屏两套横图的完整性、底栏可见性、混合比例纵向浏览及关闭详情后保留位置、工作台内换图和 100% 查看。

恢复回归覆盖原供应商任务号超时后只查询、未知任务号保持待核对、本机处理瞬时失败复用下载文件、首图审核中断自动恢复，以及审核阶段只读无 Logo 图。

传输回归还覆盖 KIE 官方 API 在回环代理环境中的直连选择、喜马拉雅先保存前一张回执再发送下一张、等待提交时停止和重启，以及已有任务查询继续并行。前端检查等待回执、正在提交、后台恢复查询和受理待核对分开显示，只有确认原请求未受理才会传本图版本发起补跑。

KIE 恢复回归使用回环 HTTP 验证普通和学习机的临时下载，校验旧网关回查路径。在真实工作台 API 上模拟查询超时、丢失已受理回执、旧回执接回、错误任务号和确认未受理。断言每条路径仅有一次成功受理。普通任务另外验证接回时沿用原版本、重复请求被拒绝。前端检查不同入口的任务号表单和版本参数。

简化回归检查普通任务启动恢复时的发送前证据、缺回执状态及卡片和详情一致性。学习机无回执恢复和普通任务超时均不得新增供应商请求。普通打包验证每张源图只验一次、旧包仍可下载，下载期间在状态锁外验包。前端验证保存直接发出一次请求，学习机只组装当前页签，切换无需发起制作请求。

1. 业务规则需要独立预期：例如CTA/无Logo/纯画面的具体版位集合，而不只比较总数，或把被测对象与自身派生结果比较。
2. 目录映射可以整套遍历验证，覆盖每个PID、图片序号、尺寸和依赖；不必为相同映射逻辑每个版位重复构造一轮。
3. 历史fixture明确冻结旧模块、尺寸、图片数、KB和圆角。辅助重建不是完整档案dump，仍须核对保留素材的哈希与实际规格；验证旧配置与当前配置故意不同时仍成立。
4. 图片硬规格验证实际编码、重新读出的宽高、字节、alpha及哈希。超限测试使用真实超限输入，并检查原图、旧成品和目标尺寸不被悄悄改动。
5. 先证明前置状态存在，再断言操作的结果，例如先确认 `pid::set` 已选择，再验证重出后取消；控件顺序先检查控件存在，防止 `indexOf=-1` 误通过。
6. 不以随机恰好抽到某种画风作为测试前提。选择范围/排除规则与具体历史格式分别验证，样本不是概率保证。
7. 每条保留测试说明能抓住什么错误。必要时用内存扰动验证断言确实会变红，不修改生产文件，也不把测试变成实现的副本。

## CI与验收范围

`.github/workflows/workbench-portability.yml` 在 Windows 和 macOS 上按多个 Python 版本验证基础安装、图片处理和离线传输。macOS 全量回归另按锁定依赖构建可选的联合量化工具。配置、素材、前端测试和量化工具源码的变更都会触发检查。定向传输任务显式取消默认 core 过滤，避免漏测。

本机通过不代表远端CI已运行，也不代表Windows实机、供应商长期并发或真实模型视觉质量已验收。真实API验证按用户明确范围另行执行，不属于自动回归。

发布回归覆盖`run.py --help`在禁止导入OpenCV/NumPy时仍能执行、仅填写两项Key保留内部默认服务、真实Git源码选择与ZIP/tar内容、本地数据库阻止发布、本机Key泄漏阻止打包且保留旧包、示例Key必须为空。CI在只安装运行依赖后额外执行入口探针；源码检查在全量回归前运行。干净安装与人工验收步骤见[发布检查](releasing.md)。

## 有字母版审核与修复

- 学习机新任务走正式模式。HTTP 回归通过规划、图片和视觉审核替身测试实际路由。检查缺 Key 时提示配置、创建接口拒绝旧模拟请求、历史任务仍可读取，前端只显示正式制作入口。

- `test_learning_visual.py` 用正式批次编排和离线供应商替身覆盖纯画面跳过、初审通过、独立复核冲突、确认缺陷后修复、修复后复审、版本和哈希门禁。复审接口暂不可用时用同一候选恢复，断言修复调用数保持为一次。
- 前端测试覆盖制作进度的文字复核按钮、旧版本保护、审核原图与成品下载的区别，以及人工决定发送当前候选版本和哈希。
- 错字局部复核回归覆盖修复图被误读为「第二步」时使用同一候选放大复核。识别为「第一步」才扩版，仍识别为「第二步」继续等待处理。网关替身检查单字和邻字裁图的实际请求，并确认期望字没有传给定位或局部盲读。
- 字面检查回归覆盖整图读数完全正确但放大后发现青色碎屑侵入黑色描边。网关替身核对实际裁出的正文和按钮输入，以及整图通过结论改为需处理。
- 已完成母版的人工清修回归检查当前哈希、版本、同组更新和原图片字节可读。重复提交沿用清修请求。
- 概念图风格回归检查原图对应的字外黑色干刷痕，保留它时仍校验正文与按钮。浅色碎斑不能走同一路径。
- 删减内容的构图回归覆盖概念图去正文和去按钮、学习机共用母版的来源内容判定以及共同裁框审核。构图失衡阻止交付和文字清修，通过整组重新构图可恢复，重复提交沿用同一请求。
- 真实验收使用独立状态和端口。新整套验证母版与版位流程，历史同哈希真实母版验证疑点保留、修复及复审。模型回执和最终像素、字节、哈希分别核对。
- 概念图 HTTP 测试覆盖横向 16:9 校验、默认 44 个版位、冻结上传字节、确认门、原图适配、GPT 扩背景、去字和按钮分流。前端测试覆盖上传说明、图上正文、全选和查看确认原图的入口。
